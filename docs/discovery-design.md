# 发现首页设计

发现首页用于浏览分类、刷新推荐、直接点播和继续最近听过的音乐。固定试听 EP 不再占据首页的大幅展示区域；真实首页内容由音源返回，推荐和历史各自维护播放队列。

## 视觉层级

- 桌面沿用 macOS 浅色窗口：浅灰窄侧栏、细分隔线、红黄绿窗口控制、底部稳定播放条。分类使用深灰底白字标识选中状态，珊瑚红用于播放、收藏及必要的当前状态。
- 全局搜索留在顶部工具栏。首页工具栏仅保留“音乐馆”，中央内容只出现一次“发现音乐”大标题，不再加重复的眉题或“音乐馆 > 发现音乐”面包屑。刷新按钮与内容标题对齐，分类置于其下。
- 首条真实推荐采用小幅横向图文组合，提供播放与详情入口；首条后接最近播放与后续推荐。后续视频封面使用 16:10 横向比例，避免强制方形裁切丢失画面信息。宽屏为三列，1600 像素以上为四列；931–1150 像素窗口与移动窄屏为两列。
- 最近播放独立采用紧凑歌曲行，桌面两列、手机一列；封面、标题和作者对齐，点按时只使用对应的历史队列。生产首页不把本地试听曲混入真实推荐，离线试听收进页面底部的折叠区。
- 右侧播放详情减为当前封面、标题、作者、实际音质及短队列，避免与中央列表竞争。窗口不超过 930 像素时隐藏右侧详情，播放仍由底部控制条承载。
- 不超过 660 像素改为移动布局：隐藏侧栏、增加底部导航、搜索保留独立工具栏、推荐两列，首条推荐改为上下图文。原型触屏按钮提供至少 44 像素有效目标；实际应用同时结合可用视口与安全区适配。

## 交互与状态

分类切换与刷新需要独立请求编号，过期响应不能覆盖新分类。刷新时保留已有内容，用按钮文字呈现状态，不使用旋转图标。失败时保留最近一次成功结果并提供重试。

推荐卡和历史行必须绑定稳定曲目标识及对应列表快照，不能用最后一次渲染列表覆盖全页索引。播放、暂停、收藏及最近播放更新不应重置内容滚动位置；进入新分类或页面时可明确回到顶部。

## 原型与实际内容

初版原型以方形封面探索基础层级；当前迭代已对齐实际首页的横向视频封面、小幅首曲推荐、独立搜索工具栏和深灰分类样式。可点击设计稿仍只使用《山间来信》的三首原创试听曲与现有封面，标题栏及内容区显著标识“设计原型 / 原型示例”，并注明不是线上推荐数据。

分类、刷新、卡片播放、收藏、最近播放、队列和底部控制可交互；不会请求网络或实际播放音频，也不把示例数据称为排行榜。原型只有三首示例，后续卡片数量少于真实首页；其分类名称、右侧详情和收藏操作用于展示交互，不代表真实音源返回字段的完整覆盖。

实际布局与内容以 `src/discovery.css` 和 `src/app.mjs` 的 `home()` 为准。仓库中的 `docs/discovery-prototype.html` 是可直接打开的独立设计稿，无需启动站点服务。
