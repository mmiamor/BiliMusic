# 音乐空间：从播放场景扩展到完整产品

## 视觉方向

暖纸、暖墨、赭红与衬线标题延续空间唱片方案。去掉占据整屏的侧栏和重复分隔线，用字体尺度、间距和柔和光色建立层次。页头、内容和底部播放控制共享背景；来源视面只保留轻微透视与高低差，不让装饰影响结果阅读。

发现页采用编辑式结构：一张主视觉与一句明确的聆听主题，然后进入四张主题封面和可试听曲目。六张抽象封面是本地 SVG，无远程图片请求。歌曲行采用紧凑文字与明确操作，避免每一行都成为独立卡片。

## 一次输入，多个来源视面

检索保留统一关键词，各来源分别呈现状态。BILI 固定在第一视面；曲目、UP 主和合集保留平台语义。酷我对应曲目、歌手、专辑；网易云对应曲目、歌手、歌单。

来源状态按当前检索代次独立更新。新关键词或筛选变化使旧回调失效；单一来源失败不覆盖其他来源的结果。状态演练可单独指定正常、空结果、失败，重试只恢复当前来源。此处的短暂加载时间用于展示交互，不代表实际平台响应时间。

桌面并列展开三个来源；手机改为纵向阅读，并保留「全部来源 / 单个来源」选择。没有横向拖动才能找到的内容。搜索结果出现后收紧顶部标题，优先让结果进入首屏。

## 连续播放与资料库

播放器只创建一次，页面路由变化不重建音频。收起空间播放器后，音乐继续，唱片的装饰动画停止；展开后恢复。主界面与播放器用单向命令、独立的用户偏好事件同步主题、动效和收藏，普通音频状态不会反向覆盖用户刚做的选择。

自建歌单保存有序条目，试听时只将有真实音轨的内置曲目交给队列。无音轨的来源示例会保留在歌单并明确说明。顺序播放在末尾停止，只有开启循环后才回到队首。

浏览器存储采用独立版本键，读取时验证字段并去重；用户文字转义后呈现。存储不可用时告知仅会话保存。登录表单只显示输入验证反馈，不模拟认证成功、不保存密码。BILI 授权以单独的流程说明呈现。

## 动态与可访问性

路由内容轻微淡入，封面轻微抬起，来源加载使用局部状态线。系统减少动态和手动开关会关闭装饰动画。主播放器沿用真实播放驱动的旋转与缓停。

主要按钮目标至少 44px。筛选与标签切换后恢复原按钮焦点；对话框使用原生 dialog，嵌套流程保留最初入口，Esc 返回；空间播放器展开时背景不可交互，收起后返回入口。手机保留固定播放控制，长页面正常滚动。

## 原型与正式接入的界限

该目录是可运行的 UI 方案。三首器乐真实播放，其余平台条目为可检索的本地示例。正式集成需要复用现有平台搜索服务、登录与歌单数据库、音质验证和 DSP 引擎，不能直接把示例状态作为线上数据。

原型仅使用本地文件，不启动 HTTP 服务，不部署到 music.cafedaily.top。
